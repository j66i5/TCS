## Hard rules (SPEC 4.3) — one line each
1. Deterministic sim: fixed 60 Hz, seeded RNG with named streams (`sim/rng.ts`), no `Math.random`, no wall clock.
2. Transcendental maths (sin, cos, sqrt, pow, exp, `**`) only via `sim/math.ts`.
3. Orders are the only external input to the sim (`submitOrder`).
4. Whole state serialisable (`serializeState`/`deserializeState`/`hashState`); components are plain data.
5. Sim emits events; render/UI/tools consume events, never internals.
6. Entities are numeric IDs, state in `Store`s (ID-ordered); projectiles in typed arrays (M2).
7. SI units inside the sim (m, s, kg, rad); convert at the UI edge.
8. No faction in code (no `"de"`/`"ru"` literals in sim/ai/render/ui); fixture faction `xf` must keep working.
9. Every consumable is a counted item in a container; one generic `transferItems`.
10. Wounds are records; casualties remain entities.
11. Battle = `runBattle(BattleInput) -> BattleResult`; roster records in and out.
12. Player-facing text via string tables (`Strings.t`); events carry keys, not text.

## Gotchas
- TypeScript is pinned to 6.0.x: typescript-eslint does not support TS 7 yet.
- `sim`, `data`, `ai`, `scenario`, `campaign` have no DOM/Node types on purpose: a type error there may mean you used a forbidden API.
- Iterate stores, never raw `Map`s of entities: insertion order breaks determinism after save/load.
- Changing any data file changes the catalog fingerprint and fails the golden test — intended changes need `npm run golden:update` + a DECISIONS.md line.
- Playwright is pre-installed in the cloud container, not a project dependency; load it via `createRequire`.
- Wikipedia and most of the web are blocked from the container; data source URLs cannot be fetched here.
- `packages/scenario` (map generation) follows the sim's determinism lint rules: maps are battle input.
- New data folders must also be bundled by the app (`packages/app/src/data.ts` glob); a test checks core/** and factions/**.
- Hot loops (projectiles): copy imported functions/constants into locals first — module getters cost ~15 % in tsx/vitest.
- Timing tests (`perf*.test.ts`) fail if another heavy command runs at the same time; run `npm run check` alone.
- `bench-vehicles` sits close to its 8× floor: new per-tick work in spotting, contacts or vehicles needs a perf check. The parked-hulls perf test is noisy (+9 to +29 % on one build): rerun alone before calling it a regression.
- A crew that bails out loses `Unit.vehicle` (gets `exVehicle`): count a side's vehicles from `state.vehicle`, not its crews. Labs shooting at a crewed hull must hold it still (penetrated crews reverse out).
- A carrier crew template is chosen from the manifest platoon's carriage (`crewTemplateOf`, M7.6c), not by id order; `platoonTemplates {tracked, wheeled}` falls back to `platoonTemplate`. Adding ammunition shifts `catalog.ammoIds`, so state hashes with projectiles in flight change (projectile ammo is an index): compare event streams, or map the index to ids.
- Men on foot look for vehicles only every fourth scan: any "seen within" window for vehicles must be at least ~5 s.
- Research cannot open web pages here (network), only search extracts: mark such data `confidence: "medium"` at most.
- The battle opens with nothing selected; `__tcs` debug-hook orders go to the first own unit then, `__tcs.select(null)` deselects. The order-bar dock is remembered in localStorage `tcs.ui.dock`.
- Appearance data (`appearance.json`) is outside the catalog fingerprint: colour changes need no `golden:update`.
- Zoom levels live in `render/src/lod.ts` (symbols < 1.2, dots, figures from 8 (always true scale), close >= 16 px/m); soldier art is string grids in `render/src/sprites/soldier-art.ts` (preview via `composeFrame`/`rotateFrame` to PNG in Node).
- Batch, headless and `npm run map` take `--no-interiors` (pre-interiors map, for comparisons). `packages/tools/golden/no-interiors/*.json` are pre-interiors goldens replayed with interiors off: never regenerate them.
- Every route for men goes through `routeBetween`; a raw `findPath` needs an `// outdoor: ok` marker (architecture test). Inner walls live in `MapIndex.segments` from `nOuter` on, not in `buckets` (use `interiorSegmentsInRectInto`).
- Every soldier height goes through `standZ`; a bare `heightAt` in `sim/src/systems` or `ai/src` needs `// ground: ok` (architecture test). Routes to upper floors need heights: `routeBetween(..., {sz, gz})` + `routeWaypoints`, never hand-built waypoints. Debug hooks `__tcs.occupyAt(x, y)`, `setFloor(f)`, `floorShown()`.
- Photo map tiles paint in a worker (`render/src/photo/worker.ts`); tests and Node use the same painter on the main thread. Screenshots must wait for `__tcs.tilesPending() === 0`. Painters in `render/src/photo/` and `flat/paint.ts` stay pure (no Pixi/DOM/random/clock; architecture test); copy imported functions and constants into locals in their pixel loops.
- Photo-only unit extras (contact shadows, rims, hull shadows, scorch, under-strokes, veil, grain) are keyed on `look === "photo"` in `renderer.ts`: flat must stay byte-identical (compare `--scene look` shots).
- Night (M9.1): `light` follows the clock only when `environment.sky` is set (`environmentAt`); without it (every golden) nothing changes. The renderer tints map, roofs and men by `state.environment.light`; at light 1 nothing night-related is drawn.
- Sensors (M9.2): a sensor kind may be `thermal` (sees heat: per-target `heat` in spotting.ts, vegetation thinned as visibility^exponent) and have `arcDeg` (a man's sight/goggle helps only within it). `SENSOR_HEAT` in spotting.ts is set by each sensor function: read it right after the call.
- Drones (M9.4): an enemy drone a man sees lives in his `seen`, never in his contacts; men look for drones every fourth scan, so "sees it" windows use `DRONE_SEEN_S` (6 s). A drone's operator is busy with the open-ended action `flyDrone`. M9.6: men hide from enemy drones (`SoldierState.droneHide`, `behaviour.soldier.droneHide`); flares light targets per target (`sim/flares.ts`); AI night drills are gated on `light < COMMANDER.night.belowLight`; `tallyReview` (sim/review.ts) feeds the review and batch lines.
- An automatic grenade launcher team (M7.6d) uses `Unit.missileTeam` (kind "agl") as its post state: test the kind with `crewServedKind`, never `missileTeam !== undefined` alone; `launcherOf` is missile posts only, `aglOf` AGL posts, `crewPostOf` either.
- Fighting positions (M11 hold battle): `state.terrain.positions` (dug only with `rules.prepared`, `sim/positions.ts`); a man in one is `inPosition` and keeps it (cover seeking, side steps, drone hiding, re-siting, bearers under fire skip him). The rim test runs only when a body would be struck: battles without positions are unchanged.
- HUD z-order: sidebar 1, dock 2, panels above, perf read-out 4, review 5, errors 6.
- Field repair (M11.7a): `onRoof` (alias `isOutside`) is true for every OUTSIDE_ACTIONS kind (reloadOutside, repairOutside, hookUp): seated but exposed like a man on foot; only `onRoofTop` (the M9.3a reloader) stands on the hull. A lab that freezes a hull with `rec.status = "immobilised"` sets `rules.repair = false` too. The repair action handlers use string literals (systems/repair.ts loads before mount.ts in an import cycle).
- Recovery (M11.7b): off-map assets now have kinds (`OffMapKind` "ambulance" | "recovery"): test `offMap.kind` when you mean ambulances, never `offMap !== undefined` alone. A hull a recovery vehicle was called for has `recoveryBy` (no wreck stamp in the nav grids; the pair do not block each other in drive.ts); on the bar it has `towedBy` (skips its own drive, follows the hitch in `towSystem`, its guns hold fire); towed off the map it has `towAway` (`isOffMap` true for good, crew aboard). The end settlement (`settleVehicles`) runs next to `settleBattle` at both battle ends (sim.ts time limit, objectives.ts side broken). `withoutRecovery(input)` (scenario) strips the assets: they come after every other entity, so ids stay as without them.
- Military police (M11.9b, `systems/mp.ts`): off-map kind "mp", created by `setup.ts` after EVERY other entity (caches, points, stocks too): ids at tick 0 are as without them, but entities made later (drones, caches) shift, so compare a branch with `withoutMp`/`--no-mp` runs, not raw against main. An evacuated prisoner keeps his `mount` pointer to the MP hull while its seat is freed for the next run: `captive.evacTick` makes him `isOffMapMan` for good; never count a hull's prisoners from soldier mounts, use `v.seats`. A prisoner walking to the hull has `captive.vehicle` set before he is aboard.
- Escapes (M11.9c): an escaping prisoner keeps `captive` (with `captive.escape`) until he is free (`captive` null: the one way back from "captured") or recaptured ("surrendered"); `held()`/`heldPrisoner` exclude him. Contacts' `surrendered` flag comes from `showsSurrender(s, tick)` (impair.ts), not `isCaptive`, and is taken back from the enemy (never from guards) after `escape.graceSeconds`. Escape rolls draw from stream "prisoners" only for an unwatched walking prisoner, once a minute staggered by id; `rules.prisonerEscapes: false` switches them off. `__tcs.burst(x, y)` bursts the enemy's mortar round (screenshots).
- D3: `__tcs.perf(reset?)` returns the frame split (always installed); perf mode never computes the state hash. Unit tests named `perf*.test.ts` are timing tests (excluded from `npm test`). The roof atlas paints in `render/src/photo/roof-worker.ts` (synchronous without workers); `tilesPending()` counts it.
- Campaign contract (M12.0a): `BattleInput.damage`/`wrecksIn` in, `BattleResult.damageOut`/`service` out only with `rules.campaignOut` (goldens unchanged without it). An earlier battle's wreck is a hull of side `WRECK_SIDE` ("-") with `wreckIn` (its old side): count a side's hulls by `v.side`, never assume every hull belongs to a force. `packages/campaign` follows the sim lint and never imports `ai` (inject a `BattleRunner`).
- Campaign record (M12.1a, `campaign/src/record.ts`): rules between battles are pure (`applyResult`, `replenish` return a new record); unit keys and person ids are prefixed "P" (player) / "E" (enemy), replacements are `<prefix>#<nextPersonId>`, replaced hulls `<crewKey>~<n>`. The battalion tree keeps every unit (empty ones too); a battle commits copies (`proposeCommit`) and the results come back by unit key. The books: start + delivered - battles' net - written off = now per item (`forceHoldings`, `bookedChange`); any new way men, hulls or items enter or leave a force must book itself there. New company/battalion data: manifest `battalionTemplates`; the catalog is cached per data set (`campaignCatalog`).
- Campaign flow (M12.2, `campaign/src/flow.ts`, `operation.ts`): every step is a pure function of the record and the phase lives in `record.flow`; the app plays the main battle from `battleInputs(...).main.input` and hands its result to `finishBattle` (the flank battle is auto-resolved there, applied first with `CampaignBattle.flank`: no clock, not an operation battle). Node types and the transition table are data (`core/campaign.json`; `checkOperationRules`). A sector's map is fixed by its kind, seed and size (`Sector`): always pass them, never let `scenarioMapSize` scale a revisited sector. Battle seeds are `hashString32("campaign/<seed>/<battles>/<main|flank>")`.
- Campaign saves (M12.1b, `campaign/src/save.ts`): a change to `CampaignRecord`'s shape that older saves cannot satisfy needs `CAMPAIGN_VERSION` + 1 and a new entry in `MIGRATIONS` (never edit a released one; optional fields an older save simply lacks, as M12.2's `op` / `operations` / `flow` / `battleSeconds`, need none); `packages/campaign/test/fixtures/campaign-v1.json` is a real M12.1a record: never regenerate it. Export is canonical JSON, so a valid save must load without a change (no repair, no normalising) or export -> import stops being byte-identical. A chain continues from the record alone (`continueCampaignChain`: a finished operation is replenished before the next battle).
- Scenario kinds (M12.0b): `ScenarioDef.kind` "platoon-attack" is "attack" (same input); new kinds set `ForceInput.plan` (the sim never reads it) and the AI takes it through `planControllers` / `sideCommander` (ai/postures.ts; no plan: the platoon commander). Exit zones (`rules.exits`): a man out is `evacuated` with `via: "exit"` (not able, `isOut`, but saved: roster "fit"/"wounded", not a man down; test `hasExited`); a hull out is `exited` (`isOffMap`). Late units (`arriveS`) bring their hulls with them (`lateHulls`, created at arrival).
- Campaign screens (M12.3): every number on a screen comes from `campaign/src/view.ts` (pure, tested); `ui/src/campaign.ts` only lays out (no campaign import: its `Cmp*` types are structural). The page keeps its working record in the automatic slot after every step; auto-resolve and the sector preview run in the Web Worker `app/src/campaign/worker.ts` (pure part `resolve.ts`), cancel = terminate. A played battle's result goes back through the store's pending key (`battleResultOf`, `?campaign=1&finish=1`). Debug hook `__tcsCampaign.state()` (screen, phase, battles, hash, busy, history).
- Campaign balance (M12.4): the enemy's commitment is the node's `enemyRatio` x the player's committed men x `fightingValue(player) / fightingValue(enemy)` (`factions/<id>/campaign.json`, outside the catalog: no golden change; 1 without the file). A new faction needs its value measured with `npm run campaign -- batch` (target success 30-70 % with the AI on both sides; DE 3.0 still gives DE 100 % / RU 0 %: the gap is in the mounted battle, not the ratios); the batch report's tuning lines (experience over an operation, able share, failure reasons, recovery days) are what DECISIONS M12.4 quotes.
- Campaign review fixes: every "able men" count of a choice goes through `deployableMen` (crews of hulls in the workshop or lost rest, as `commitOf` strips them); campaign battles in the app are built with `CAMPAIGN_HOOKS` (app/src/campaign/hooks.ts, = tools `ON_POSTS`); a played result and the mid-battle save match the record by `hashRecord`; `CampaignSave.rulesFingerprint` covers `core/campaign.json` and the factions' campaign blocks (outside the catalog fingerprint).
- Area fire and air burst (balance pass 5, `systems/gunnery.ts`): a crew with no live target under fire "free" fires at `crewSuspects` (derived from its men's contacts, nothing stored); its station task carries `area` (circle, weight, interval, the burst's offset) and `fuse: "airburst"`. A round's air-burst setting is ammo data (`airburst`, fuse "programmable"; `cone` = KETF payload thrown forward, `ejectCone` in explosions.ts); the fuze is the projectile pool's `burstTick` (0 = none, saved only when a live row has one, so states without air bursts hash as before). Rows written straight into the pool (fragments) must set `burstTick` 0. `vehicle.areaFire` events per burst. The player's default fire rule is "return": no automatic area fire for his hulls until he sets "free" (owner Q9).
- Mounted assault (balance pass 5, `systems/assault-mounted.ts`): an `assault` order to riders, a crew, or a platoon with carriers takes the mounted form (`Unit.mountedAssault` on the unit ordered; `mountedAssaultApplies`); never after a dismount (the squad's own `then` assault is the foot drill). Move, halt, assault, withdraw, occupy, mount, dismount and defendArc orders take the units they reach out of it (`leaveMountedAssault`). `dismountSpot` and `siteSupportPost` are pure and shared with the AI commander: change the siting there, not in commander.ts. Without `behaviour.mounting.mountedAssault` (the sim test catalog) an assault to riders dismounts them first, as before. Dismount distance only through `dismountDistance` (doctrine `dismountM`, or `dismountUrbanM` when `isBuiltUp`), the men-threat radius through `threatMenFor`; `assault.dismounted` carries a `reason` (labs).
- The Stop hook (`.claude/hooks/stop-check.sh`) blocks ending the session on red checks; escape hatch documented in the script.
