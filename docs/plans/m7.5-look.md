## 0. Facts the plan depends on (code as of M7.4)
- Buildings: `MapDef.buildings[]` (`sim/src/map.ts`): footprint (rotated rect, wall 0 = front), storeys,
  storeyHeightM, wall material/thickness, `openings[]` (ground floor only, from `openingsFor()` in
  `scenario/src/mapgen/builder.ts`), roofColour. No floors in between.
- Nav: buildings are solid (`computeWindow()` in `sim/src/nav.ts`). No man ever stands inside.
  `backblastBlocked()` in `systems/launcher.ts` uses the footprint as "room".
- Sight: `los.ts sight()` tests segments (`segmentsInRectInto(mapIndex)`), roofs via a footprint-crossing loop
  (`B.roofs`, `roofBuckets`), hulls, ground/vegetation. `systems/ballistics.ts` uses the same segments and
  `segInfo` (`SegInfo{heightM, openings, built}`), bucket bit `NW` and `roofLow` as pre-filters. `lineBlocked()`
  ignores roofs. `applyBreaches()` adds holes to `seg[].openings` by (owner, id, part).
- Heights: `Transform.z` = height above ground (0 on foot). Body hits and explosions use `hAt + t.z`; spotting
  (`spotting.ts` ~211), fire/launcher/grenade muzzles use `heightAt + posture` and ignore `t.z`.
- Fingerprints: `mapFingerprint`, `catalogFingerprint` are in the hashed state. Terrain kinds (incl. colour) are
  in the catalog fingerprint; faction manifest extras are not. Map generation uses named RNG streams.
- Renderer (`render/src/renderer.ts`): one immediate-mode Graphics for units; men are discs; `OVERVIEW_SCALE=0.35`
  px/m switches to unit symbols; labels from a Text pool with no collision handling (overlap the owner saw).
  Terrain (`render/src/terrain.ts buildTerrain`): one blended ground canvas with hill shading and contours.
  Camera 0.05–40 px/m; app opens ~600 m across with `selectedUnit = topUnits[0]`.
- UI (`ui/src/hud.ts`): order bar is a flex-wrap row (wraps on phones); `ordersFor()` in `ui/src/orders-for.ts`
  only tells foot from vehicle (a squad without a launcher still gets Anti-tank).
- Perf guards: `render/test/perf-render.test.ts` (< 4 ms), `tools/test/perf.test.ts` (bench-vehicles ≥ 8×).

## 1. Invariants
1. M7.5a and M7.5b are presentation only: no sim/scenario/catalog-visible change; goldens untouched. Look
   values go into a new **appearance** data set outside the catalog fingerprint.
2. M7.5c changes the map once: interiors for all floors (rooms, inner walls, stairs, upper windows) generated
   there; goldens regenerated once. M7.5d adds behaviour only used when a man is ordered into a building
   (golden-neutral for existing scenarios).
3. Equivalence proof in c: with `generateMap(..., { interiors: false })` map, catalog and every golden are
   bit-identical to before. Requires no data file change in c (slabs reuse roof material/thickness).
4. Outdoor routes byte-identical: the outdoor nav grid is untouched; interiors are a separate graph joined at doors.
5. No faction literals: uniform tones are appearance data keyed by faction id; `xf` gets its own entry; neutral fallback.
6. All art original, generated in code (pixel grids in TS); log in `docs/ASSETS.md`.

## 3. M7.5a — UI shell — ✅ done 2026-11-12
Built as below with these differences (DECISIONS.md "M7.5a UI shell: implementation choices"): label grid 8 px
(16 px was too coarse), labels also keep off other labelled symbols, HUD strips and the screen edge; capability
kind is none/group/man/vehicle (echelon not needed); the bar's "⋯" applies to the vertical docks too; in a only the
vehicle paint of the appearance data is drawn (uniforms and palette in b). Screenshots `npm run screenshot -- --scene ui`.
- `ui/src/orders-for.ts`: `unitCapabilities(view, catalog, unitId)` (pure, SimView only): kind
  squad/team/vehicle/man, foot, hasLauncherRounds (same test as `launcher.ts chooseLauncherAmmo`), handGrenades,
  rifleGrenades, support (battery with rounds), canMount/canDismount (move `boardingOf` here from `main.ts`),
  passengers, hasSmokeDischargers, natures. `ordersFor(cap, modes)`: Anti-tank only with launcher rounds;
  grenades only with grenades; mortar/smoke only with support; "man": move, fire, grenade, posture, halt, cease
  fire. `none: true` = nothing selected, all buttons disabled.
- `ui/src/hud.ts`: `setOrders(set | null)` (null = greyed). Order bar its own fixed element `dock-<edge>` with a
  grip; drag snaps to the nearest edge (pure `nearestEdge` in new `ui/src/dock.ts`), remembered in localStorage
  `tcs.ui.dock` (try/catch). Horizontal: one row, nowrap, overflow-x auto, rare buttons behind "⋯". Vertical: one
  column. `insets()` so the app passes the free area to `renderer.focus`/`fitToMap`.
  Default dock: bottom in portrait, right in landscape.
- New `ui/src/sidebar.ts`: pure `unitTiles(view, side, catalog)`; slim strip of 56 px tiles (left by default,
  right if the bar docks left); tap selects; head expands the full list; always open ≥ 1000 px; refresh ~4/s.
- `app/src/main.ts`: start with `selectedUnit = null`; wire sidebar and capabilities; keep `__tcs.select`.
- New `render/src/labels.ts`: greedy `placeLabels` over a 16 px occupancy grid, 4 anchors, selected first then by
  id, drop what doesn't fit; width estimated chars×7 px. Dismounted squad within 15 m of its vehicle gets one
  combined label. Overview: vehicle symbol (original design); infantry symbols only for units with men on foot.
- Appearance data: `packages/data/factions/<id>/appearance.json` (`uniform {base,dark,light,helmet,skin}`,
  `vehicle {hull,dark}`) and `packages/data/core/appearance.json` (flat palette per surface/vegetation/roof/floor).
  `buildAppearance()` beside `buildCatalog`, NOT in the catalog/fingerprint (test asserts it). Schema, lint,
  `app/src/data.ts` glob.
- Tests: orders-for (capabilities), dock, sidebar, labels (no overlap, selected always placed), appearance
  (fingerprint unchanged, xf fallback). Goldens unchanged; perf-render < 4 ms.
- Screenshots `--scene ui`: nothing selected, squad, vehicle, docks left/top/right, sidebar expanded, overview.

## 4. M7.5b — Look — ✅ done 2026-11-12
Built as below with these differences (DECISIONS.md "M7.5b Look"): close level at 16 px/m (not 12) = the art's own
16 px per metre; sprites drawn at max(true size, ~24 CSS px snapped to whole device pixels) for phone readability;
facings pre-rotated in the atlas (Scale2x) rather than rotated on the GPU; the selected unit gets a thin white ring
(not a white outline); detail tiles and the base map come from one pure painter (`paintRegion`, no canvas); the
roof layer is a container per map with one Graphics per building; one-row top bar with "⋯", compact status line and
the camera clamped to the map (parent review). Screenshots `npm run screenshot -- --scene look`.
- New `render/src/lod.ts`: `CLOSE_SCALE = 12` px/m (true scale; man sprite covers 1 m), `FIGURE_SCALE = 5`,
  `SYMBOL_SCALE = 1.2` (replaces OVERVIEW_SCALE); 10 % hysteresis. Opening view: focus on the lead unit at
  `OPENING_SCALE = 8` px/m.
- New `render/src/sprites/`: `soldier-art.ts` original 16×16 frames as string grids (facing east; letters
  u d l h s w g f r x .): stand, walk1, walk2, crouch, prone, fire-stand, fire-crouch, fire-prone, wounded overlay,
  down, dead, surrender, captive; weapon variants by `WeaponDef.type` (rifle, mg, marksman, launcher on back).
  `atlas.ts`: RGBA atlas per faction by palette swap, Pixi texture from a buffer, nearest scaling; side marker = 1-px
  outline mask tinted blue/red. Renderer: `menLayer` with a sprite pool (2 per man), rotation snapped to 16 steps,
  firing frame for a few ticks after `shot.fired`, walk frames while moving. Rings stay in the Graphics layer;
  disc path stays for the dot band.
- Flat pixel map `render/src/terrain-flat.ts` (old kept behind `?look=classic` for one milestone): one flat
  colour per cell, no blend, no hill shading, nearest sampling; pixel tree crowns with outline; contours as a
  separate sprite visible only zoomed out; detail tiles 64 m at 4 px/m built lazily (≤1 per frame, LRU 48) for
  close zoom; roads/water/walls/hedges flat with thin outline, no antialias.
- `render/src/buildings.ts`: floorLayer, roofLayer (one Graphics per building), per-building alpha animated.
  Roof fade: alpha 0 when scale ≥ CLOSE_SCALE or an own able man not aboard is inside or within 8 m (bucket grid).
- Tests: atlas (16×16, palette letters, deterministic, outline non-empty), lod hysteresis, roof-fade pure
  function, perf-render close case (~270 men at 12 px/m < 4 ms) and roofs case. Goldens unchanged.
- Screenshots: opening, mid, far, firing squad close-up, wounded/down/surrendered, roof faded vs shown, village
  and farmland mid zoom. Before/after pairs.

## 5. M7.5c — Interiors
- Map data (`sim/src/map.ts`, MAP_FORMAT_VERSION 1→2; v1 = no interiors): `Opening.floor?`; `Room {id, floor,
  poly (convex, CCW), kind room|hall|stair}`; `InnerWall {id, floor, ax, ay, bx, by, thicknessM, material,
  doors[{offsetM, widthM, headM}]}`; `Stair {id, floor, room, x0, y0, x1, y1, widthM}`;
  `Building.interior?: {rooms, walls, stairs}`. `validateMap`: rooms convex inside footprint, all reachable from
  an exterior door, every floor has rooms, doors on walls. `mapgen/stats.ts` reports problems.
- Generation `scenario/src/mapgen/interiors.ts`: `furnishInteriors(builder)` after all buildings, id order, new
  stream `"mapgen/interiors"`; MAPGEN_VERSION 2; option `interiors` (default true). BSP in local frame, min room
  2.5 m; house/farmhouse 2–5 rooms with a hall at the front door; office corridor + rooms; apartment stair core +
  flats; barn/warehouse/church/shed one room. Each split one 0.9 m doorway (tree), 30 % a second. Same partition on
  every floor. Stairs 1 m wide, 3–4 m long, same place each floor pair. Upper windows: copy ground windows per
  floor and a window above every door.
- Derived: `buildMapIndex` appends inner segments after existing ones (owner "building", part = nOuter + i), not
  in `buckets`; `MapIndex.interiorOf`, `interiorBuckets`. `SegInfo.baseM`; openings normalised by floor;
  `applyBreaches` unchanged. Slabs at k×storeyH with the kind's roof material/thickness; bucket bit `NI`.
  `sight()`: inside the roof loop, for crossed buildings with interiors test inner segments and slabs.
  `systems/ballistics.ts`: with `NI` and below roof, test inner segments and slabs (slab = lower roof record).
  `lineBlocked()`: inner segments and slabs between floors.
- Interior nav `sim/src/interior-nav.ts`: per-building graph (doorway nodes ±0.4 m, exterior doors in/out,
  breaches, stairs in d), complete graph inside each convex room; Dijkstra with index tie-breaks.
  `routeBetween(ctx, from, to, opts)`: outdoor→outdoor = `findPath` as now; outdoor→indoor via cheapest door/breach;
  symmetric. `Waypoint.z?`, `inside?` (schema bump). Route all men's `findPath` call sites (orders.ts, decisions.ts,
  drills.ts, surrender.ts, grenades.ts, boarding.ts) through it when an end is indoor; vehicles untouched.
  `nearestPassable` keeps indoor destinations. Indoors: no formation, room spots. Indoor cover: `seekCoverIndoor`.
  `backblastBlocked` uses the man's room.
- Render: floor layer per building/floor (floor colour, outer walls with door gaps and windows, inner walls,
  stair hatching); debug draws the interior graph.
- Tests: interior (sight through doorway/blocked, window, slab, projectile vs inner wall, breach opens path,
  lineBlocked); interior-nav (cheapest door, no wall crossings, determinism, breach rebuild); nav grid identical
  with interiors on/off; mapgen validity all kinds × 5 seeds, `interiors:false` identical map, < 150 ms; goldens
  regenerated + equivalence test (pre-c goldens kept as `packages/tools/golden/no-interiors/*.json` replayed with
  interiors off); batch on vs off; architecture test (`// outdoor: ok` marker); perf floors + village LOS ≤ +10 %.

## 7. Design questions — decided with the recommended option (to confirm with the owner)
1. Zoom: true scale from 12 px/m; dots+symbols 1.2–5; symbols below 1.2; open at 8 px/m on the lead squad.
2. Sprite facing: free rotation snapped to 16 directions.
3. Sprite size: 16×16 px art per 1 m.
4. "Man" actions: a unit of one able man (no single-man selection inside a squad yet).
5. Order bar default dock: bottom in portrait, right in landscape; remembered per device.
6. Sidebar vs left-docked bar: sidebar moves to the right.
7. Floor plans: same partition on every floor.
8. Doors: always-open doorways, no door state.
9. Slab material: reuse roof material/thickness (no data change in c).
10. Stairwell holes: ignored for sight and projectiles.
11. Dark-room concealment: none for now.
12. Interiors for all building kinds; big halls one room.
13. Entering through windows: doors and breaches only.
14. AI use of buildings: a separate later slice (M7.5e), owner-confirmed.
15. Enemy floor badge on contacts: only while seen.
16. Roof fade: own men within 8 m or zoom ≥ 12 px/m.
17. `?look=classic` kept for one milestone.
